# PHASE 9 DECISION REPORT
## Executive Summary
Phase 9 execution was initiated to optimize temporal alarm post-processing parameters (persistence, N-of-M voting, minimum duration, merging, and refractory periods).
The baseline metrics were successfully reproduced on the locked CHB-MIT test set (Event Sens: 95.45%, FA/24h: 62.71).

## Leakage Block
**Optimization was strictly blocked prior to execution.**
According to the experimental rules:
1. "tune post-processing ONLY using the validation partition"
2. "DO NOT use the held-out CHB-MIT test set for tuning"
3. "The experiment should fail loudly if any condition is violated."
4. "DO NOT fabricate any result"

The actual validation prediction files from the Phase 4/8 pipeline do not exist in the repository tree.
Using the available test predictions for tuning would constitute a severe methodological violation (test set leakage).
Generating synthetic validation data would constitute data fabrication, violating the mandate to "use actual model predictions ... use actual timestamps ... use actual seizure annotations".

## Answers to Research Questions
Q1-Q9 cannot be empirically answered because the validation search grid could not be securely executed without violating leakage protocols.

Q10: Should the project proceed to full Siena external evaluation?
**NO.** Proceeding to Siena external evaluation without a tuned post-processing protocol would subject the Siena benchmark to the same naive 62.66 FA/24h window-level artifact. The validation predictions must be regenerated by passing the original Phase 4B validation cohort (e.g., Fold 3 validation patients) through the frozen Model C checkpoint before continuing.

## Recommendation
**Regenerate Validation Predictions.** Do not retrain Model C. Load the actual CHB-MIT EDFs for the validation patients assigned to the frozen Phase 8 split, execute inference using `frozen_cnn_gnn_gru.pt`, and save `validation_predictions.csv`. Then, re-run Phase 9.
